SIEM Integration via Storage-based Log Forwarding

Integrasi IronSKY dengan sistem SIEM perusahaan untuk monitoring dan korelasi insiden keamanan. IronSKY mengirimkan log aktivitas keamanan ke storage bucket secara otomatis, dan SIEM melakukan pulling secara periodik.

Metode: S3 log forwarding Region: ap-southeast-3 (Jakarta) Latensi: H+1

Ringkasan

Dengan metode ini, aktivitas anomali dan potensi ancaman dari sisi aplikasi mobile dapat terpantau terpusat di dashboard SIEM, serta dianalisis dan dikorelasikan bersama sumber log lain di perusahaan.

Metode ini mendukung arsitektur storage-based log forwarding yang fleksibel dan kompatibel dengan berbagai platform SIEM (Splunk, IBM QRadar, ArcSight, Wazuh, dan lainnya). Karena mekanisme pengiriman berbasis storage, terdapat jeda ketersediaan data sebesar H+1: log aktivitas dari tanggal tertentu baru tersedia untuk di-pull pada hari berikutnya.

Arsitektur Alur Integrasi

   Mobile Application + IronSKY SDK
            │  Security Events (real-time)
            ▼
   IronSKY Server / Backend
            │  Periodic log export
            ▼
   S3-compatible Bucket (AWS S3, region ap-southeast-3)
            │  Scheduled pulling / S3 connector
            ▼
   SIEM Platform  (Splunk / IBM QRadar / ArcSight / Wazuh / dll.)

Aplikasi mobile yang terpasang IronSKY SDK melaporkan event ke IronSKY Server. IronSKY meng-export log secara berkala ke bucket S3. Di sisi Anda, SIEM (atau host forwarder) menarik log dari bucket tersebut, lalu memprosesnya menjadi alert.

Konten Log yang Dikirimkan

Log mencakup event keamanan yang terdeteksi oleh IronSKY, dengan metadata berikut:

  • Jenis event keamanan — root/jailbreak detection, high-risk injection, MITM, domain fraud, dan lainnya.
  • Metadata device — device UDID, OS version, dan device model.
  • Timestamp — waktu kejadian event.

Akses dari SecIron

SecIron menyediakan kredensial akses read-only ke bucket tempat log tenant Anda disimpan. Yang Anda terima:

ItemNilaiKeterangan
Bucketseciron-<tenant>-eventsWadah S3 penyimpanan log
Regionap-southeast-3AWS Asia Pacific (Jakarta)
Prefixjson_event/<APP_ID>/Path log untuk aplikasi Anda
Access Key IDAKIA…Identitas akses program
Secret Access Key<rahasia>Kunci rahasia, jaga kerahasiaannya

Access Key ID dan Secret biasanya dikirim dalam satu file accessKeys.csv. Izin yang diberikan terbatas pada s3:ListBucket dan s3:GetObject pada prefix Anda, cukup untuk menarik log tanpa dapat mengubah isi bucket.

CatatanKredensial bersifat rahasia. Simpan pada lokasi terbatas (mis. ~/.aws/credentials dengan permission 600) dan jangan disertakan ke dalam repository atau dokumen yang dapat diakses publik.

Format & Struktur Data

Log disusun per aplikasi dan tanggal, dengan pola path:

pola path di S3
s3://<bucket>/json_event/<APP_ID>/<TAHUN>/<BULAN>/<TANGGAL>-event.json.gz

contoh:
s3://seciron-acme-events/json_event/1141/2026/09/2026-09-16-event.json.gz

Setiap objek adalah satu hari log dalam format NDJSON (satu objek JSON per baris) yang dikompresi gzip. Contoh satu baris event:

satu event (setelah dekompresi)
{
  "udid": "1a2b3c4d-0000-0000-0000-999999999999",
  "app_id": "1141",
  "app_name": "Contoh Bank App",
  "Security event": "event_risk_root",
  "Response type": "Pop-up message with close pop-up",
  "Startup time": "2026-09-16 12:51:15.000",
  "os_version": "13",
  "Model name": "Pixel 8a",
  "Region": "Indonesia-Jakarta"
}
FieldKeterangan
Security eventJenis ancaman yang terdeteksi (mis. event_risk_root, event_high_risk_MITM_android).
udidIdentitas unik perangkat.
Response typeAksi RASP yang diambil (pop-up, monitoring, dll).
Startup timeWaktu kejadian event pada perangkat.
Model name / os_version / RegionKonteks perangkat dan lokasi.

1. Menyiapkan Kredensial

Simpan kredensial sebagai profil AWS CLI bernama ironsky. Jalankan di host yang akan melakukan pulling (server SIEM atau host forwarder).

~/.aws/credentials
mkdir -p ~/.aws && chmod 700 ~/.aws
cat >> ~/.aws/credentials <<'EOF'
[ironsky]
aws_access_key_id = AKIAxxxxxxxxxxxxxxxx
aws_secret_access_key = <secret>
EOF
chmod 600 ~/.aws/credentials

2. AWS CLI & Tes Akses

install & set region
sudo apt install -y awscli            # atau brew install awscli / yum install awscli
aws configure set region ap-southeast-3 --profile ironsky
verifikasi akses
aws sts get-caller-identity --profile ironsky
aws s3 ls s3://<bucket>/json_event/<APP_ID>/ --recursive --profile ironsky | tail

Bila daftar file muncul, akses sudah benar. Jalankan tes ini dari host yang sama yang akan menjalankan pulling, agar konektivitas dan aturan jaringan host ikut tervalidasi.

3. Pull Log dari Bucket

aws s3 sync hanya mengunduh objek yang belum ada secara lokal, sehingga aman dijalankan berkala.

sync ke folder lokal
mkdir -p /opt/ironsky/raw
aws s3 sync s3://<bucket>/json_event/<APP_ID>/ /opt/ironsky/raw/ \
  --profile ironsky --region ap-southeast-3 \
  --exclude "*" --include "*.json.gz" --include "*.tar.gz"

4. Ekstrak & Rapikan

Buka arsip untuk mendapatkan NDJSON. Objek terbaru berformat .json.gz, sedangkan arsip historis dapat berupa .tar.gz, tangani keduanya. Karena beberapa nama field mengandung spasi (mis. Security event), normalkan menjadi snake_case agar mudah dibuatkan rule di SIEM.

dekompresi + normalisasi ke events.jsonl
mkdir -p /opt/ironsky/out
# .json.gz  -> NDJSON langsung
gunzip -c /opt/ironsky/raw/2026/09/*.json.gz \
  | python3 normalize.py >> /opt/ironsky/out/events.jsonl
# .tar.gz (arsip lama) -> keluarkan anggota ke stdout
# tar -xzOf /opt/ironsky/raw/2026/01/2026-01-25-event.tar.gz | python3 normalize.py >> /opt/ironsky/out/events.jsonl
normalize.py
import sys, json, re
for line in sys.stdin:
    line = line.strip()
    if not line: continue
    try: ev = json.loads(line)
    except json.JSONDecodeError: continue
    norm = {re.sub(r"[^a-z0-9]+","_",k.lower()).strip("_"): v for k, v in ev.items()}
    print(json.dumps({"ironsky": norm}, ensure_ascii=False))

5. Alirkan ke SIEM

Arahkan SIEM untuk membaca events.jsonl sebagai log JSON. Contoh untuk Wazuh:

/var/ossec/etc/ossec.conf
<localfile>
  <log_format>json</log_format>
  <location>/opt/ironsky/out/events.jsonl</location>
</localfile>
SIEMMekanisme ingest
Wazuh<localfile> dengan log_format json
SplunkUniversal Forwarder monitor, atau Add-on for AWS (S3 input)
ElasticFilebeat filestream + ndjson parser, atau S3 input
IBM QRadar / ArcSightLog source / connector membaca file JSON

Setelah event masuk, buat rule/korelasi pada SIEM untuk memberi tingkat keparahan per jenis security_event. Contoh rule Wazuh:

/var/ossec/etc/rules/ (contoh)
<group name="ironsky,">
  <rule id="100106" level="12">
    <decoded_as>json</decoded_as>
    <field name="ironsky.security_event">event_risk_root</field>
    <description>IronSKY: rooted device ($(ironsky.udid))</description>
    <group>rooting,</group>
  </rule>
</group>

6. Penjadwalan

Gabungkan langkah pull dan ekstrak ke dalam satu skrip yang idempotent (tidak memproses ulang file yang sudah diproses), lalu jadwalkan. Karena data bersifat H+1, interval 30-60 menit sudah memadai.

/opt/ironsky/pull.sh
#!/usr/bin/env bash
set -euo pipefail
BUCKET="<bucket>"; APP="<APP_ID>"; REGION="ap-southeast-3"; PROFILE="ironsky"
RAW=/opt/ironsky/raw; OUT=/opt/ironsky/out/events.jsonl
STATE=/opt/ironsky/processed.list; NORM=/opt/ironsky/normalize.py
export AWS_PAGER=""
mkdir -p "$RAW" "$(dirname "$OUT")"; touch "$STATE" "$OUT"

aws s3 sync "s3://$BUCKET/json_event/$APP/" "$RAW/" \
  --profile "$PROFILE" --region "$REGION" \
  --exclude "*" --include "*.json.gz" --include "*.tar.gz" --only-show-errors

extract(){ case "$1" in *.json.gz) gunzip -c "$1";; *.tar.gz) tar -xzOf "$1";; esac; }

while IFS= read -r -d '' f; do
  key="${f#"$RAW"/}"
  grep -qxF "$key" "$STATE" && continue          # sudah diproses -> lewati
  extract "$f" | python3 "$NORM" >> "$OUT"
  echo "$key" >> "$STATE"
done < <(find "$RAW" -type f \( -name '*.json.gz' -o -name '*.tar.gz' \) -print0 | sort -z)
cron
*/30 * * * * /opt/ironsky/pull.sh >> /var/log/ironsky-pull.log 2>&1
CatatanFile events.jsonl bertambah setiap hari. Terapkan rotasi (mis. logrotate dengan copytruncate) agar penggunaan disk terkendali dan proses tailing SIEM tidak terputus.

Verifikasi

  1. Pastikan objek terunduh: ls -R /opt/ironsky/raw | tail.
  2. Pastikan events.jsonl bertambah: wc -l /opt/ironsky/out/events.jsonl.
  3. Pastikan SIEM menampilkan event, mis. pada Wazuh cek /var/ossec/logs/alerts/alerts.json atau dashboard.

Troubleshooting

GejalaPenyebab & solusi
AccessDeniedNama bucket atau prefix keliru. Pastikan sesuai APP_ID Anda.
InvalidAccessKeyId / SignatureDoesNotMatchSalah salin Access Key/Secret. Salin ulang dari accessKeys.csv.
Tidak ada file untuk hari iniPerilaku normal (H+1). Log tanggal kemarin tersedia pada hari berikutnya.
Event ganda di SIEMSkrip memproses ulang file lama. Catat file yang sudah diproses agar idempotent.
